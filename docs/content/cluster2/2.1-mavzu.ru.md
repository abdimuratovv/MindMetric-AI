## Вход, выход и контракт

Алгоритм — точные шаги от заданного входа к требуемому выходу. Сначала запишите исходные данные, результат и допустимые значения.

Вход поступает от пользователя, выход вычисляется. Для периметра прямоугольника вход — стороны a и b, выход — P = 2 × (a + b). Длины должны быть положительными.

До вычисления согласуйте единицы. Недостаточно получить правильное число: определите его смысл и единицу измерения.

### Разобранный пример

Одна тетрадь стоит 4000 сумов, количество — 3. Найдите общую стоимость.

1. Вход: цена и количество.
2. Итого = 4000 × 3 = 12000.
3. Выход — общая стоимость в сумах.

Ответ: 12000 сумов

### Практика — `algo-io-practice-1`

Один билет стоит 6000 сумов. Сколько сумов стоят 4 билета?


Ключ: 24000

1. Цена умножается на количество.
2. 6000 × 4 = 24000.

Типичная ошибка: Сложение цены и количества не даёт общую стоимость.

Подсказка: Одинаковая цена относится к каждому билету.


### Практика — `algo-io-practice-2`

Нужно вычислить ПЛОЩАДЬ прямоугольника, а не длину окружности. Какие вход и выход подходят?

- a) Вход: радиус r; выход: длина окружности
- b) Вход: a, b; выход: 2 × (a + b)
- c) Вход: стороны a, b; выход: a × b

Ключ: c

1. Для площади берутся две стороны.
2. Используется формула S = a × b.

Типичная ошибка: Даже при одинаковом входе не подменяйте цель результата.

Подсказка: Площадь измеряет внутреннюю область.

- a: Это другая фигура и другая величина.
- b: Это даёт периметр, а не площадь.
- c: Двух сторон достаточно для площади.

### Входная проверка — `algo-io-precheck`

Для нахождения времени пути заданы расстояние и постоянная скорость. Какое ограничение необходимо?

- a) Расстояние всегда равно скорости
- b) Скорость положительна, единицы согласованы
- c) Скорость обязательно равна нулю

Ключ: b

1. Время = расстояние / скорость.
2. Скорость должна быть положительной, единицы — согласованными.

Типичная ошибка: Вместе с формулой указывайте условия её применения.

- a: Для разных физических величин такого требования нет.
- b: Выполняется деление на скорость; ноль и несогласованные единицы недопустимы.
- c: Делением на ноль время не найти.

### Итоговая проверка — `algo-io-postcheck`

На складе 18 коробок, в каждой 12 предметов. Найдите количество предметов.


Ключ: 216

1. Выход — число предметов, а не коробок.
2. 18 × 12 = 216.

Типичная ошибка: Не принимайте само количество коробок за ответ.


## Декомпозиция задачи

Декомпозиция делит большую задачу на небольшие проверяемые части. Для каждой части определяются вход, выход и связь со следующей частью.

При расчёте заказа сначала проверьте данные, затем найдите сумму товаров, примените скидку и в конце добавьте доставку. Порядок следует из условия задачи.

Отдельная проверка части сужает поиск ошибки. Не каждый экран или строка — самостоятельная задача: часть должна иметь осмысленный результат.

### Разобранный пример

Из стоимости товара 20000 сумов вычитают скидку 5000 сумов, затем добавляют доставку 3000 сумов. Выполните этапы.

1. Сумма товаров — 20000.
2. После скидки 20000 − 5000 = 15000.
3. С доставкой 15000 + 3000 = 18000.

Ответ: 18000 сумов

### Практика — `algo-decompose-practice-1`

В каком порядке удобно построить программу среднего балла?

- a) Среднее → получить оценки → сумма
- b) Только выбрать цвет окна
- c) Получить оценки → проверить → сумма и количество → среднее

Ключ: c

1. Вход и проверка идут первыми.
2. Результаты вычислений последовательно передаются следующей части.

Типичная ошибка: Не ставьте вычисление раньше его входных данных.

Подсказка: Что предыдущий этап передаёт каждому следующему?

- a: Среднее нельзя вычислить по ещё не полученным данным.
- b: Это не разбивает вычислительную задачу на части.
- c: До деления подготовлены сумма и делитель.

### Практика — `algo-decompose-practice-2`

Товар стоит 80000 сумов. Сначала скидка 10000 сумов, затем доставка 5000 сумов. Каков итог?


Ключ: 75000

1. 80000 − 10000 = 70000.
2. 70000 + 5000 = 75000.

Типичная ошибка: Не вычитайте доставку как скидку.

Подсказка: Скидка уменьшает сумму, доставка увеличивает.


### Входная проверка — `algo-decompose-precheck`

Список может быть пустым. Какая подзадача нужна до вычисления среднего?

- a) Проверить, что количество элементов не равно нулю
- b) Заранее округлить результат
- c) Удалить все оценки

Ключ: a

1. Делитель — количество элементов.
2. Если оно равно нулю, вместо среднего возвращается состояние пустого списка.

Типичная ошибка: Проверка пустого входа должна предшествовать вычислению.

- a: Это предотвращает деление на ноль.
- b: Округление ещё не вычисленного значения не решает случай пустого списка.
- c: Это уничтожает нужные данные.

### Итоговая проверка — `algo-decompose-postcheck`

Расчёт: 3 товара по 20000 сумов; скидка с общей суммы 15000 сумов; затем доставка 7000 сумов. Итого?


Ключ: 52000

1. 3 × 20000 = 60000.
2. 60000 − 15000 + 7000 = 52000.

Типичная ошибка: Не вычитайте общую скидку из цены каждого товара.


## Последовательность и присваивание

В псевдокоде x ← выражение означает присваивание, x == y — сравнение. Сначала вычисляется правая часть, затем обновляется левая переменная.

Действия выполняются в записанном порядке. x ← x + 1 увеличивает прежнее значение; это не уравнение для решения.

При обмене двух значений нужна временная t: t ← a; a ← b; b ← t. Иначе одно значение будет перезаписано и потеряно.

### Разобранный пример

x ← 4; y ← x + 3; x ← y × 2. Чему равно конечное x?

1. Сначала x равно 4.
2. y = 4 + 3 = 7.
3. Новое значение x равно 7 × 2 = 14.

Ответ: 14

### Практика — `algo-assignment-practice-1`

x ← 5; x ← x + 2; x ← x × 3. Чему равно конечное x?


Ключ: 21

1. После обновления x = 7.
2. Затем x = 7 × 3 = 21.

Типичная ошибка: В последнем действии не используйте снова исходное значение.

Подсказка: Обновляйте таблицу значений после каждой строки.


### Практика — `algo-assignment-practice-2`

a ← 2; b ← 9; a ← b; b ← a. Чему равно конечное a + b?


Ключ: 18

1. После a ← b значение a = 9.
2. После b ← a значение b = 9; сумма равна 18.

Типичная ошибка: Это не обмен: временной переменной нет.

Подсказка: При первом присваивании прежнее значение a теряется.


### Входная проверка — `algo-assignment-precheck`

a ← 6; b ← 4; t ← a; a ← b; b ← t. Чему равно конечное b?


Ключ: 6

1. t сохраняет прежнее a, равное 6.
2. Из-за b ← t получаем b = 6.

Типичная ошибка: Не путайте сохранённое значение с последующим a.


### Итоговая проверка — `algo-assignment-postcheck`

x ← 3; y ← x × 2; x ← y − 1; y ← x + y. Чему равно конечное y?


Ключ: 11

1. y = 6, затем x = 5.
2. y = 5 + 6 = 11.

Типичная ошибка: Берите последнее значение каждой переменной.


## Символы и переходы блок-схемы

Обозначения курса: овал — начало/конец; параллелограмм — ввод/вывод; прямоугольник — действие; ромб — условие. У каждого символа также есть текстовая подпись.

Стрелки показывают порядок выполнения. Из ромба выходят ветви TRUE и FALSE. Отличайте вычисление от условия.

Текстовая запись тоже описывает схему: START → INPUT x → DECISION x > 0; TRUE → OUTPUT положительное → END; FALSE → OUTPUT неположительное → END. Каждый путь должен завершаться или возвращаться к указанному повторению.

### Разобранный пример

Выберите символы для проверки «n чётное?» и для вывода n.

1. Вопрос является условием, поэтому нужен ромб.
2. Вывод — операция ввода/вывода, нужен параллелограмм.
3. Из условия выходят две подписанные ветви.

Ответ: Ромб; параллелограмм

### Практика — `algo-symbols-practice-1`

В какой блок записывается действие x ← x + 1?

- a) Прямоугольник
- b) Ромб
- c) Овал

Ключ: a

1. Значение вычисляется и записывается.
2. Вычислительный блок — прямоугольник.

Типичная ошибка: Не заменяйте вычисление сравнением.

Подсказка: Эта команда задаёт вопрос или изменяет значение?

- a: Это действие обновления значения.
- b: Здесь нет вопроса с ответом истина/ложь.
- c: Овал предназначен для начала или конца.

### Практика — `algo-symbols-practice-2`

Какая ветвь выбирается из DECISION x ≥ 10 при x = 10?

- a) FALSE
- b) Обе ветви одновременно
- c) TRUE

Ключ: c

1. 10 ≥ 10 истинно.
2. Поэтому выбирается ветвь TRUE.

Типичная ошибка: Не забывайте равенство на границе.

Подсказка: Знак ≥ включает равенство.

- a: ≥ означает не только строго больше.
- b: Один результат проверки выбирает одну ветвь.
- c: Равенство входит в условие ≥.

### Входная проверка — `algo-symbols-precheck`

Какой блок относится к вводу/выводу?

- a) Овал
- b) Параллелограмм
- c) Ромб

Ключ: b

1. INPUT и OUTPUT обмениваются данными.
2. Они изображаются параллелограммом.

Типичная ошибка: Определяйте блок по его назначению.

- a: Овал обозначает начало или конец выполнения.
- b: Это обозначение ввода/вывода в курсе.
- c: Ромб обозначает условие.

### Итоговая проверка — `algo-symbols-postcheck`

Схема: START → INPUT x → DECISION x < 0; TRUE → OUTPUT 1 → END; FALSE → OUTPUT 0 → END. Каков выход при x = 0?

- a) 0
- b) 1
- c) Выхода нет

Ключ: a

1. 0 < 0 ложно.
2. Ветвь FALSE выводит 0 и завершается.

Типичная ошибка: Не выбирайте выход, не проверив подпись ветви после ромба.

- a: Ноль не отрицателен, выбирается FALSE.
- b: Это выход ветви TRUE.
- c: В ветви FALSE тоже есть OUTPUT.

## Пошаговая проверка алгоритма

В таблице трассировки отдельно записываются значения переменных после команды и выведенные значения. OUTPUT показывает значение, но не меняет переменную.

Различайте обычный, граничный и недопустимый вход. Если требуется положительный возраст, ноль или отрицательное значение нужно отклонить до вычисления.

Один успешный пример не доказывает правильность на всех входах. Сначала проследите малые примеры вручную, затем ищите контрпример.

### Разобранный пример

x ← 2; OUTPUT x; x ← x + 5; OUTPUT x. Какова последовательность выводов?

1. Первый OUTPUT выводит 2.
2. После обновления x = 7.
3. Второй OUTPUT выводит 7.

Ответ: 2, 7

### Практика — `algo-trace-practice-1`

a ← 8; OUTPUT a; a ← a − 3; OUTPUT a. Запишите только последнее выведенное число.


Ключ: 5

1. Первый вывод — 8.
2. После обновления a равно 5, последний вывод — 5.

Типичная ошибка: Не путайте первый и последний вывод.

Подсказка: После OUTPUT выполнение команд продолжается.


### Практика — `algo-trace-practice-2`

n должно быть положительным целым. Какой набор охватывает обычный, граничный и недопустимый случаи?

- a) 0, −1, −2
- b) 5, 1, 0
- c) 5, 6, 7

Ключ: b

1. Требование: n > 0.
2. Минимальное допустимое — 1, проверьте и стоящий ниже 0.

Типичная ошибка: Не ограничивайтесь примерами одного типа.

Подсказка: Найдите крайнюю точку выполнения требования.

- a: В этом наборе нет допустимого случая.
- b: 5 — обычное, 1 — минимальное допустимое, 0 — недопустимое.
- c: Все значения допустимы и не граничны.

### Входная проверка — `algo-trace-precheck`

x ← 7; y ← x; x ← 2; OUTPUT y. Каков выход?


Ключ: 7

1. В y копируется текущее значение 7.
2. Изменение x не изменяет y.

Типичная ошибка: Не считайте копирование значения постоянной связью.


### Итоговая проверка — `algo-trace-postcheck`

Алгоритм «находит максимум для любых a и b» выполняет OUTPUT a только при a > b. Какой вход выявляет недостаток?

- a) a = 5, b = 2
- b) a = 9, b = 1
- c) a = 2, b = 5

Ключ: c

1. Возьмите случай, когда a > b не выполняется.
2. Даже если b больше, результат должен выводиться.

Типичная ошибка: Проверка только работающей ветви не проверяет другой путь.

- a: На этом входе выводится большее a, недостаток не выявляется.
- b: Это тоже успешный случай, когда a больше.
- c: Условие ложно, но должно выводиться 5; алгоритм ничего не выводит.
