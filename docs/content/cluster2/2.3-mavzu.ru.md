## for и границы повторения

В курсе for i ← a TO b {действие} увеличивает целое i от a до b; обе границы включены. При a > b тело не выполняется. Это отличается от правила Python range.

Счётчик хранит значение итерации, накопитель — общий результат. Для суммы s ← 0 записывается до цикла; в теле выполняется s ← s + i.

Обнуление накопителя на каждом проходе теряет прежнюю сумму. Отдельно отслеживайте число выполнений тела и значение на каждом проходе.

### Разобранный пример

s ← 0; for i ← 1 TO 4 {s ← s + i}. Чему равно s?

1. Значения i: 1, 2, 3, 4.
2. Значения s: 1, 3, 6, 10.
3. Конечная сумма — 10.

Ответ: 10

### Практика — `loop-for-practice-1`

s ← 0; for i ← 2 TO 5 {s ← s + i}. Чему равно s?


Ключ: 14

1. Обе границы включены.
2. 2 + 3 + 4 + 5 = 14.

Типичная ошибка: Не пропускайте конечную границу.

Подсказка: Сначала выпишите все значения i.


### Практика — `loop-for-practice-2`

p ← 1; for i ← 1 TO 3 {p ← p × 2}. Чему равно p?


Ключ: 8

1. Тело выполняется 3 раза.
2. p: 2, 4, 8.

Типичная ошибка: Не путайте число умножений с суммой значений i.

Подсказка: Каждый раз прежнее p удваивается.


### Входная проверка — `loop-for-precheck`

c ← 0; for i ← 3 TO 7 {c ← c + 1}. Чему равно c?


Ключ: 5

1. Значения: 3, 4, 5, 6, 7.
2. Их 5, значит c = 5.

Типичная ошибка: Число повторов не обязано равняться последнему i.


### Итоговая проверка — `loop-for-postcheck`

s ← 9; for i ← 5 TO 3 {s ← s + i}. Чему равно s по правилам курса?


Ключ: 9

1. Начало больше конца.
2. Тело возрастающего for не выполняется, s = 9.

Типичная ошибка: TO не задаёт скрытый убывающий шаг.


## while и условие завершения

while проверяет условие до тела. Если оно изначально FALSE, тело не выполняется ни разу. После каждого прохода условие проверяется снова.

Состояние цикла должно изменяться так, чтобы условие однажды стало FALSE. Отсутствие шага вроде i ← i + 1 или уменьшения остатка может привести к бесконечному циклу.

Вместо предположения о завершении укажите, что уменьшается или приближается к границе. Знаки в условии и обновлении должны согласовываться.

### Разобранный пример

x ← 1; while x < 8 {x ← x × 2}. Чему равно конечное x?

1. x: 1 → 2 → 4 → 8.
2. 8 < 8 ложно.
3. Тело больше не выполняется, x = 8.

Ответ: 8

### Практика — `loop-while-practice-1`

x ← 3; c ← 0; while x < 12 {x ← x + 3; c ← c + 1}. Чему равно c?


Ключ: 3

1. Тело работает при начальных x: 3, 6, 9.
2. При x = 12 цикл останавливается, c = 3.

Типичная ошибка: Не считайте проверку остановки ещё одним выполнением тела.

Подсказка: Условие каждый раз проверяется до тела.


### Практика — `loop-while-practice-2`

i ← 0; while i < 4 {OUTPUT i}. Чего не хватает?

- a) Добавить больше OUTPUT
- b) Обновления i в теле, приближающего его к границе
- c) Каждый раз делать i ← 0

Ключ: b

1. Значение i в теле не меняется.
2. Например, i ← i + 1 приводит к завершению.

Типичная ошибка: Не считайте OUTPUT обновлением состояния.

Подсказка: Как достичь значения, делающего условие ложным?

- a: Вывод не меняет i.
- b: Если i не меняется, условие остаётся истинным.
- c: Это возвращает состояние к началу и не помогает завершению.

### Входная проверка — `loop-while-precheck`

x ← 10; c ← 0; while x < 5 {c ← c + 1; x ← x + 1}. Чему равно c?


Ключ: 0

1. Изначально 10 < 5 ложно.
2. Тело не выполняется, c = 0.

Типичная ошибка: Предположение, что while работает хотя бы один раз, неверно.


### Итоговая проверка — `loop-while-postcheck`

x ← 20; c ← 0; while x > 2 {x ← x div 2; c ← c + 1}. Чему равно c?


Ключ: 3

1. Целочисленное деление: 20 → 10 → 5 → 2.
2. 2 > 2 ложно, c = 3.

Типичная ошибка: div отбрасывает дробную часть; не заменяйте его обычным делением.


## do-while: сначала тело, затем условие

do {тело} while условие сначала выполняет тело, затем повторяет его, если условие TRUE. Поэтому тело выполняется хотя бы один раз.

Это не repeat-until: при истинном условии while выполнение ПРОДОЛЖАЕТСЯ. Обращение смысла условия приводит к ошибке.

Подходит для меню или процесса с обязательной первой попыткой. Вход всё равно нужно проверять; обязательное выполнение не заменяет проверку допустимости.

### Разобранный пример

x ← 5; do {x ← x + 1} while x < 3. Чему равно конечное x?

1. Тело сначала делает x равным 6.
2. 6 < 3 ложно.
3. Повторения нет, x = 6.

Ответ: 6

### Практика — `loop-do-practice-1`

x ← 0; do {x ← x + 2} while x < 5. Чему равно конечное x?


Ключ: 6

1. Значения после тела: 2, 4, 6.
2. 6 < 5 ложно, x = 6.

Типичная ошибка: Не останавливайте цикл на значении до достижения границы.

Подсказка: Проверяйте условие по обновлённому значению.


### Практика — `loop-do-practice-2`

c ← 0; do {c ← c + 1} while FALSE. Чему равно c?


Ключ: 1

1. Первое тело выполняется без проверки.
2. FALSE прекращает повторение, c = 1.

Типичная ошибка: Не ставьте начальную проверку перед телом.

Подсказка: Первый шаг do-while — тело.


### Входная проверка — `loop-do-precheck`

x ← 9; do {x ← x − 4} while x > 3. Чему равно конечное x?


Ключ: 1

1. Сначала x = 5, условие истинно.
2. Затем x = 1, условие ложно.

Типичная ошибка: do-while при истинном условии не завершается, а продолжается.


### Итоговая проверка — `loop-do-postcheck`

Изначально условие FALSE. Сколько раз выполняются тела while и do-while? В теле условие тоже остаётся FALSE.

- a) Оба: 1
- b) while: 0; do-while: 1
- c) Оба: 0

Ключ: b

1. while проверяет заранее.
2. do-while проверяет после первого тела.

Типичная ошибка: Смотрите на место проверки, а не на название.

- a: while не входит при ложном начальном условии.
- b: Места проверки различаются.
- c: do-while сначала выполняет тело.

## Трассировка вложенных циклов

На каждом проходе внешнего цикла внутренний начинается заново. При независимых границах число выполнений общего тела равно произведению повторов.

В for i ← 1 TO 2 {for j ← 1 TO 3 {...}} пары обходятся построчно. Не находите число пар сложением количества повторов.

Если внутренняя граница зависит от i, произведения недостаточно: считайте повторы отдельно для каждого внешнего значения. Работа треугольной формы может быть 1 + 2 + ...

### Разобранный пример

c ← 0; for i ← 1 TO 2 {for j ← 1 TO 3 {c ← c + 1}}. Чему равно c?

1. Внешний цикл — 2 раза.
2. Каждый раз внутренний — 3 раза.
3. c = 2 × 3 = 6.

Ответ: 6

### Практика — `loop-nested-practice-1`

c ← 0; for i ← 1 TO 3 {for j ← 1 TO 4 {c ← c + 1}}. Чему равно c?


Ключ: 12

1. На каждом внешнем проходе 4 внутренних.
2. 3 × 4 = 12.

Типичная ошибка: Не складывайте числа повторов.

Подсказка: Для каждого внешнего значения внутренний цикл идёт заново.


### Практика — `loop-nested-practice-2`

c ← 0; for i ← 1 TO 3 {for j ← 1 TO i {c ← c + 1}}. Чему равно c?


Ключ: 6

1. Числа внутренних повторов: 1, 2, 3.
2. 1 + 2 + 3 = 6.

Типичная ошибка: При зависимой границе не считайте внутреннюю длину постоянной.

Подсказка: Отдельно запишите границу j для каждого i.


### Входная проверка — `loop-nested-precheck`

s ← 0; for i ← 1 TO 2 {for j ← 1 TO 3 {s ← s + i}}. Чему равно s?


Ключ: 9

1. При i = 1 число 1 добавляется три раза, при i = 2 число 2 — три раза.
2. 3 + 6 = 9.

Типичная ошибка: Число выполнений тела и накапливаемое значение — не одно и то же.


### Итоговая проверка — `loop-nested-postcheck`

c ← 0; for i ← 1 TO 4 {for j ← 1 TO i {c ← c + 1}}. Чему равно c?


Ключ: 10

1. Числа внутренних повторов: 1, 2, 3, 4.
2. Сумма — 10.

Типичная ошибка: Учитывайте зависимость внутренней границы от внешнего счётчика.


## Рекурсия и базовый случай

Рекурсивная функция вызывает себя для меньшей задачи. Базовый случай сразу возвращает ответ и не создаёт нового вызова.

S(n): if n == 0 {RETURN 0} else {RETURN n + S(n − 1)}, n — неотрицательное целое. Каждый вызов уменьшает аргумент и ведёт к базовому случаю.

Вызовы сначала углубляются, ответы возвращаются назад. Рекурсия не бесплатна: незавершённые вызовы занимают стек. Недостаточная база или неверное направление ведут к незавершению.

### Разобранный пример

Найдите S(3) по правилу выше.

1. S(3) = 3 + S(2), S(2) = 2 + S(1).
2. S(1) = 1 + S(0), S(0) = 0.
3. Возвращаясь назад: 1, 3, 6.

Ответ: 6

### Практика — `loop-recursion-practice-1`

F(0) = 1; при n > 0 F(n) = n × F(n − 1). Чему равно F(4)?


Ключ: 24

1. F(4) = 4 × 3 × 2 × 1 × F(0).
2. F(0) = 1, результат — 24.

Типичная ошибка: Не делайте базу произведения нулевой.

Подсказка: Распишите вызов до базового случая.


### Практика — `loop-recursion-practice-2`

Для n ≥ 0 функция G(n) вызывает только G(n + 1), база — n == 0. В чём проблема при n > 0?

- a) Самого наличия базы достаточно
- b) Аргумент удаляется от базы
- c) Рекурсия автоматически уменьшает аргумент

Ключ: b

1. n + 1 увеличивает положительный аргумент.
2. Пути к базе нет, направление нужно исправить.

Типичная ошибка: Помимо записи базы обоснуйте достижение базы.

Подсказка: Приближается ли аргумент к базе при каждом вызове?

- a: Нужно ещё достичь базы.
- b: Положительное значение растёт и не достигает нуля.
- c: Изменение определяется записанным выражением.

### Входная проверка — `loop-recursion-precheck`

H(0) = 2; при n > 0 H(n) = H(n − 1) + 3. Чему равно H(3)?


Ключ: 11

1. H(1) = 5, H(2) = 8.
2. H(3) = 11.

Типичная ошибка: Не теряйте исходное базовое значение.


### Итоговая проверка — `loop-recursion-postcheck`

R(0) = 0; при n > 0 R(n) один раз вызывает только R(n − 1). Сколько всего вызовов, включая базовый, при R(4)?


Ключ: 5

1. Аргументы: 4, 3, 2, 1, 0.
2. С исходным и базовым — 5 вызовов.

Типичная ошибка: Не забывайте исходный вызов, считая только рекурсивные переходы.
