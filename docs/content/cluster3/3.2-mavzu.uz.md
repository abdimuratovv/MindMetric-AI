## Vazifalar va modul shartnomasi

Natija: Ishni mas’ul, kirish, chiqish va qabul mezoni bilan taqsimlaysiz.

Modul foydali alohida natija beradi: katalog kitob ma’lumotini topadi, berish moduli mavjud nusxani qarzga beradi. Vazifa nomi bilan birga mas’ul, bog‘liqlik va tugallanish mezoni yoziladi.

Shartnomada parametrlar, natija va xato holati kelishiladi. Masalan, find_book(book_id) topilmasa None qaytaradi. Biri None, boshqasi {} kutsa, kodlar alohida ishlasa ham birgalikda buziladi.

“Tugadi” degani kod yozildi emas: shartnoma testlari o‘tgan, kerakli izoh va hamkor reviewsi bor. To‘siqni erta aytish va yangi kelishuvni yozish jamoaning vaqtini tejaydi.

## Juftlikda dasturlash

Natija: Driver va navigator vazifalarini hamda foydali rol almashishni tushuntirasiz.

Driver klaviaturada kod yozadi va niyatini ovoz chiqarib tushuntiradi. Navigator talab, keyingi qadam, test va xavflarni kuzatadi. Ikkalasi ham faol fikrlaydi; navigator tomoshabin emas.

Rolni kichik vazifa tugaganda yoki kelishilgan qisqa davrda almashtiring. Almashishdan oldin joriy holat, keyingi test va ochiq savol aytiladi. Tez yozuvchi doim driver bo‘lib qolmasin.

Fikrlar farq qilsa, talab va kichik testga qayting. “Sen noto‘g‘ri” o‘rniga “bo‘sh kirishda nima bo‘ladi?” deyish muammoni tekshirishga yordam beradi.

3. Natija bilan qaror qilinadi.

Javob: Ha, bu foydali talab/test savoli.

## Fayl holati va commit

Natija: Working tree, staging va commit mazmunini farqlaysiz.

Working tree — fayllarning joriy nusxasi. git add tanlangan mazmunni staging (indeks)ga oladi. git commit indeksdagi holatni mahalliy tarixga yozadi. Commitni masofaviy serverga uzatish uchun alohida push kerak.

git status holatni ko‘rsatadi. git diff odatda working tree bilan indeks farqini, git diff --staged esa indeks bilan HEAD farqini ko‘rsatadi. Adddan keyingi yangi tahrir avtomatik stagingga kirmaydi.

Kichik mazmunli commit bir vazifa yoki tuzatishni tushuntiradi. Commitdan oldin diff va testni ko‘ring. O‘quv mashqlarida ham parol va tokenlarni commitga qo‘shmang.

### Ishlangan misol

Tracked note.txt avval v1. Uni v2 qildingiz, git add note.txt; keyin v3 qildingiz. Commit nima saqlaydi?

1. Add paytida indeksga v2 olindi.
2. Keyingi v3 faqat working treeda.
3. Oddiy git commit indeksdagi v2 ni saqlaydi.

Javob: Commit v2; ishchi faylda v3 qoladi.

## Branch, review va birlashtirish

Natija: Kichik o‘zgarishni alohida branchda ko‘rib chiqib birlashtirish oqimini tanlaysiz.

Branch alohida ish yo‘lini beradi. O‘quv oqimi: kelishilgan bazadan branch, kichik o‘zgarish, test, commit, review, so‘ng maqsad branchga merge. Pull request hosting xizmatidagi review vositasi; mahalliy Gitning o‘zi emas.

git merge feature joriy branchga feature tarixini birlashtiradi. Avval joriy branchni tekshiring. Konfliktsiz merge mazmuniy to‘g‘rilikni kafolatlamaydi: natija test va shartnoma bilan tekshiriladi.

Review uchun nima o‘zgargani, nima sababdan va qanday tekshirilgani yoziladi. Hamkor fikri qayta tekshiriladi; tasdiqdan keyingi yangi tuzatish ham tegishli review/testdan o‘tadi.

### Ishlangan misol

Joriy branch main, toza holat. feature da katalog testi o‘tgan. git merge feature qaysi branchni yangilaydi?

1. Joriy branch main ekanini tekshiring.
2. Merge feature ni main ga oladi.
3. Birlashtirilgan holatda testni qaytaring.

Javob: main yangilanadi; integratsiya testi baribir kerak.

Ishora: Merge qaysi branchga ta’sir qiladi?

2. O‘zgarish va tekshiruvni ko‘ring.

Keng tarqalgan xato: Merge buyrug‘ini kontekstsiz bermang.

## Konflikt va umumiy natija

Natija: Konfliktni talab bilan hal qilib, integratsiya va himoya dalilini tayyorlaysiz.

Bir joydagi mos kelmaydigan o‘zgarishlarda Git konfliktni ko‘rsatishi mumkin. <<<<<<<, ======= va >>>>>>> markerlari yakuniy kod emas. Har ikki tomondagi niyatni o‘qib, talabga mos yakuniy variant yoziladi.

Faqat bir tomonni ko‘r-ko‘rona olish boshqa talabni yo‘qotadi. Markerlarni olib tashlagach sintaksis, shartnoma va umumiy oqim test qilinadi; hal qilingan fayl add qilinadi va merge yakunlanadi.

Loyiha himoyasida har ishtirokchi o‘z moduli, interfeysi, bitta xato holati va umumiy natijadagi rolini tushuntiradi. Demo bilan birga test dalillari ko‘rsatiladi; commitlar soni shaxsning hamkorlik qobiliyati bahosi emas.

### Ishlangan misol

Bir branch limitni 3, ikkinchisi 5 qildi. Kelishilgan talab: bir o‘quvchiga ko‘pi bilan 4 kitob. Konflikt yechimi?

1. Ikkala variant talabga mos emas.
2. Limitni 4 qilib, markerlarni tozalang.
3. 3, 4 va 5 kitob holatlarida talabni tekshiring.

Javob: Uchinchi, kelishuvga mos variant zarur.
