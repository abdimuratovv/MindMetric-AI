## Сигнатура, параметр и результат

Результат: Выделяете значение по умолчанию, параметр и тип результата.

Документация StudyTools 1.0: take(items, limit=2) возвращает новый список из первых не более limit элементов. limit — неотрицательное целое; items не меняется. Значение по умолчанию применяется, если параметр не передан.

Тип результата и количество — разные понятия. take возвращает список; len(take(...)) — его длину. Если вход короче, возвращаются имеющиеся элементы; take не дополняет список искусственно.

Именованный параметр limit=3 делает смысл явным. Не придумывайте имена, которых нет в сигнатуре. Вместо догадки о побочном эффекте проверяйте явное условие вроде «items не меняется».

### Разобранный пример

StudyTools 1.0: take(items, limit=2) возвращает новый список первых элементов. Результат take([8, 4, 9])?

1. limit не передан, берётся 2.
2. Первые два элемента — 8 и 4.
3. Результат — новый [8, 4].

Ответ: [8, 4]

### Практика — `learn-signature-practice-1`

StudyTools 1.0: take(items, limit=2) берёт первые не более limit элементов. Чему равно len(take([5, 6, 7, 8]))?


Подсказка: Если параметр не передан, используется значение из сигнатуры.

Ключ: 2

1. limit по умолчанию 2.
2. Длина результата 2.

Типичная ошибка: Не считайте длину входа длиной результата.


### Практика — `learn-signature-practice-2`

Документация: take(items, limit=2), вход не меняется. xs=[3, 8, 1]; чему равно xs после take(xs, limit=1)?

- a) [3, 8, 1]
- b) [3]
- c) []

Подсказка: Что документация говорит о побочном эффекте?

Ключ: a

1. Разделите возвращённый результат и вход.
2. xs не меняется.

Типичная ошибка: Получение результата не всегда означает изменение входа.

- a: Возвращается новый список, вход сохраняется.
- b: Это возвращённый результат, а не сам xs.
- c: Документация не говорит об удалении элементов.

### Входная — `learn-signature-precheck`

2. Допускается до 4, но возвращается имеющийся 1.

Типичная ошибка: Не считайте лимит обязательной длиной результата.

## Минимальный работающий пример

StudyTools 1.0: find(items, target, default=None) возвращает индекс первого совпадения с нуля; при отсутствии — default. find([6, 9], 6) возвращает 0. Индекс 0 не означает отсутствие.

## Ограничение, ошибка и версия

Результат: Выбираете вызов с учётом ограничений и различий версий.

StudyTools 1.0: clip(x, low=0, high=10) возвращает число в замкнутом [low, high]: ниже — low, выше — high, внутри — x. При low > high возникает ValueError. Функция не меняет x на месте.

Для take отрицательный limit даёт ValueError, нецелый или bool — TypeError. Эти ограничения нельзя узнать из имени, их читают в документации. Перехват ошибки не равен исправлению её причины.

Только для упражнения по сравнению версий сигнатура StudyTools 2.0 задана как take(items, *, count=2): count передаётся только по имени. Это симуляция, её нет в локальном файле 1.0. Не смешивайте старое имя limit с новой сигнатурой.

### Разобранный пример

StudyTools 1.0: clip(x, low, high), при low > high возникает ValueError. Разберите clip(5, low=9, high=2).

1. Сравните границы: 9 > 2.
2. Интервал нарушает контракт.
3. Результат — не число, а ValueError.

Ответ: Сначала исправьте причину неверных границ.

### Практика — `learn-limits-practice-1`

Подсказка: Какова верхняя граница?

Ключ: 9

1. 14 больше верхней границы 9.
2. Результат 9.

Типичная ошибка: clip не возвращает выходящее за интервал число без ограничения.


### Практика — `learn-limits-practice-2`

- a) Всегда []
- b) ValueError
- c) Последние 2 элемента

Подсказка: Прочитайте раздел исключений.

Ключ: b

1. Проверьте ограничение.
2. -2 отрицателен, ValueError.

Типичная ошибка: Не угадывайте семантику по похожему API.

- a: Документация явно задаёт исключение.
- b: Переданный limit нарушает контракт.
- c: Не переносите догадку о срезах Python в этот API.

### Входная — `learn-limits-precheck`

Ключ: a

1. * в сигнатуре делает count именованным.

Типичная ошибка: Не смешивайте версии в одном вызове.

- a: count передан по имени.

### Итоговая — `learn-limits-postcheck`

## Перенос в новую задачу и заметка

Результат: Применяете прочитанное правило к новому входу и записываете проверяемую заметку.

Перенос — не запоминание чисел примера, а решение нового случая по правилу. Для take «не более» означает, что из короткого списка берут имеющиеся элементы. Проверьте другую длину и другой limit.

Заметка должна быть краткой: вопрос, средство/версия, сигнатура, рабочий пример, граница или ошибка и источник. «Всё понятно» недостаточно для повторного использования.

Сначала проверьте точность, затем по желанию запишите время. При затруднении уменьшите вопрос, перечитайте пример и ограничение. Не судите об общей скорости обучения человека по времени одного занятия.

1. 5 — лимит, а не обязательная длина.
2. Вернутся имеющиеся 2 книги.
3. Запишите версию, вызов и границу короткого входа.
