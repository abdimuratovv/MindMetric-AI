## Сопоставление требования и diff

Результат: Проверяете соответствие изменения требованию и область его влияния.

Ревью начинается с требования: что должно измениться и что сохраниться? В diff знак + обозначает добавленную строку, - удалённую; это не арифметические операторы кода. Читайте и окружающий код.

Сначала проверьте функциональное требование, затем точность и читаемость. Красивый формат не оправдывает неверное вычисление. Даже небольшой diff может изменить проверку доступа или граничное поведение.

Ревью даёт вопрос или предложение с основанием. Если код уже правильный, не выдумывайте дефект: одобрение с указанием проверенного требования и подтверждения тоже правильно.

### Разобранный пример

Требование: принимать 10 и больше. Diff:
```diff
-ok = x > 10
+ok = x >= 10
```
Как проверить изменение?

1. Требование включает равенство.
2. Сравните 9, 10 и 11.
3. Новое условие исправляет именно границу.

Ответ: 9 отклоняется, 10 и 11 принимаются; diff соответствует требованию.

2. Оцените diff относительно неё.

- a: Даёт критерий правильности.
- b: Даже маленький diff может нарушать требование.
- c: Формат полезен, но сначала нужен критерий поведения.

## Имена, операторы и блоки

Результат: Проверяете смысл изменения символа или отступа.

Похожие имена могут быть разными переменными: total и tota1, count и counts. Определено ли имя и означает ли нужное? Не ограничивайтесь взглядом, найдите определение и использования.

В Python = присваивает, == сравнивает. >= и > различаются на равенстве. and/or меняют условие. Блоки Python определяются отступами; точка с запятой в конце строки не обязательна.

Называйте вид проблемы точно: неопределённое имя может вызвать ошибку выполнения, а неверно выбранное определённое имя — тихо дать неверный результат. Не переносите синтаксис из другого языка по догадке.

### Разобранный пример

Python 3:
```python
total = 12
tota1 = 2
print(tota1)
```
Требуется вывести total. В чём проблема?

1. Оба имени определены.
2. Print использует имя с цифрой 1 на конце.
3. Результат 2, нужно 12.

Ответ: Логическая ошибка выбора имени; нужен print(total).

2. Не требуйте ; для Python.

- a: Перенесено правило другого языка.
- b: Это не меняет выводимое значение.
- c: Python допускает завершение строки без неё.

## Граничный случай и инвариант

Результат: Находите нарушающий вход и свойство, которое должно сохраняться.

Инвариант — свойство, сохраняемое в процессе. Число доступных экземпляров библиотеки не должно быть отрицательным — это такой критерий. Проверяйте его после каждого шага.

Граничные входы: пустой список, один элемент, последний индекс, значение на лимите. Контрпример опровергает утверждение кода: если «максимум любых чисел» работает только на положительных, отрицательный список выявит дефект.

Ожидаемый результат теста не копируют из кода. Сначала запишите требование, затем независимо вычислите результат. Прохождение одного теста не является общим доказательством.

### Разобранный пример

max_value начинает с best=0, затем берёт больший элемент. Требование: максимум непустого списка целых. Что будет для [-5, -2]?

1. Ни один элемент не больше 0.
2. Код оставит 0.
3. Настоящий максимум -2; best можно начать с первого элемента.

Ответ: 0 неверно; отрицательные числа стали контрпримером.

### Практика — `review-boundaries-practice-1`

Экземпляров 0. borrow уменьшает число на 1 без проверки. Какой инвариант нарушен?

- a) Цвет должен меняться с каждым коммитом
- b) Число доступных экземпляров не должно быть отрицательным
- c) Экземпляров всегда должно быть 100

Подсказка: Можно ли взять ещё один при 0?

Ключ: b

1. Вычислите число после выдачи.
2. -1 противоречит требованию доступности.

Типичная ошибка: Проверяйте допустимость до обновления состояния.

- a: Это не относится к инварианту данных.
- b: 0 − 1 = -1.
- c: Такое требование не задано.

- a) []
- b) [7]

Подсказка: Какова минимальная длина списка?

Ключ: a

Типичная ошибка: Не считайте любой список непустым.

- a: Первого элемента нет.

- a: Отклоняет допустимое равенство.

### Итоговая — `review-boundaries-postcheck`

Требование: максимум положительных и отрицательных чисел. Какой контрпример выявит проблему best=0?

- a) [0, 4]

- a: В этом примере получится 4.

## Точное и уважительное замечание

Результат: Формулируете замечание с местом, требованием, контрпримером и предложением.

Хорошее замечание указывает место в коде, случай нарушения требования и его последствие. «В этом условии x=0 ошибочно отклоняется, требование разрешает ноль» — проверяемая мысль.

Отличайте обязательное исправление от личного вкуса: укажите дефект, вопрос или необязательное стилевое предложение. Комментарий относится к коду и фактам, а не способностям человека.

Если автор не понял, приведите небольшой пример. Вы тоже можете ошибиться: после уточнения требования обновите замечание. Цель ревью — проверенное хорошее изменение, а не победа в споре.

### Разобранный пример

Код x > 0, требование x >= 0. Напишите замечание вместо «Плохой код!».

1. Укажите проблемное условие.
2. Приведите контрпример x=0.
3. Предложите >= и граничный тест.

Ответ: «x=0 отклоняется, хотя требование его принимает. Можем использовать >= и добавить тест 0?»

- c) Что-то не понравилось

Подсказка: Сможет ли автор написать тест по замечанию?

Ключ: a

1. Свяжите замечание с точным входом.
2. Укажите исправление или вопрос.

Типичная ошибка: Личная оценка не является доказательством.

- a: Есть место, требование и предложение проверки.
- b: Личное суждение не помогает исправить код.
- c: Проблема не определена.

## Повторная проверка исправления

Результат: Проверяете код, тест и общее влияние до закрытия замечания.

Сообщение «исправлено» не является подтверждением. Снова проверьте обновлённый diff, тот же контрпример и соседние требования. Если новая правка расширила область ревью, проверьте и её.

Помогает короткий список: требование; имя/оператор/блок; пустой и граничный случай; сохранение состояния при отказе; тест; лишние изменения. Список помогает думать, а не механически ставить галочки.

В конце ревью укажите проверенные случаи и оставшиеся ограничения. Вместо бесконечного повторения одного вопроса сохраняйте подтверждение проверки.

### Разобранный пример

Замечание: 0 ошибочно отклонён. После исправления 0 прошёл, но -1 тоже прошёл. Закрыть ревью?

1. Требование отклоняет отрицательные значения.
2. Успех теста 0 недостаточен.
3. Попросите устранить регрессию для -1.

Ответ: Нет, есть новая регрессия.

Ключ: c

1. Посмотрите новое содержимое.
2. Повторите ранее падавший случай.

Типичная ошибка: Различайте сообщение и проверку.

- a: Конкретной проверки нет.
- b: Не показывает новое состояние.
